## 首轮发现与修正

最初后端完整测试有 40 项失败。测试仍使用旧的 9 人配置、3000 初始金币、旧身份卡内容、动态建摊方式和旧 helper 签名；当前种子数据是 19 人、600 初始金币、固定合作社摊位。已修正这些过期前提，按当前调度错峰时序检查决策、失败重试和每日计数，保留余额、账本、事件、约束、存档和财政资金分配断言。

针对性测试与完整测试曾因共用固定测试库相互影响；已改为每个 pytest 进程使用独立临时数据库，并重新执行验证。本文件仅记录隔离后的有效结果。

数据库启动已改为 Alembic，原本忽略字段或唯一索引错误的逻辑已移除。SQLite 迁移失败会回滚，基线会检查已有必要字段、类型及关键索引；不兼容的旧库必须提供专用迁移或恢复备份。

依赖审计发现的通告已通过兼容版本更新清理，CI 加入审计检查。

## CI 与发布状态

新增 `Delivery checks` 的 backend、frontend、delivery 三个 job，含测试结果/失败日志上传；`v*` tag 必须重跑完整检查并匹配版本号后才创建 Draft Release。

本轮验证在本地执行，GitHub Actions 尚未远端运行。维护者还需推送变更并在 GitHub 配置必需检查；不能仅凭 workflow 文件认定分支保护已启用。

真实模型服务、公网鉴权、其他数据库、跨平台桌面环境不属于本轮验收结果。升级和恢复步骤见 [升级指南](upgrading.md)。
